# GroupThink

A native iOS social productivity app built to help friend groups study together through shared accountability. Study Hall leverages Apple's Screen Time APIs to temporarily block distracting apps during active group sessions.

Unlike strict parental control apps, Study Hall leans into peer pressure—members can see a live "Focus Roster" showing who stayed on task, who left early, and who opened a blocked app.

## Features

- **Group Study Halls:** Create groups with friends using unique invite codes.
- **On-Device App Blocking:** Uses Apple's `FamilyControls` and `ManagedSettings` to enforce custom blocklists or "Strict Mode" whitelists locally on each member's device.
- **Live Presence Roster:** Real-time Firestore sync shows the status of every participant (Focused, On Break, Left Early, Opened App).
- **Background Tracking:** A `DeviceActivityMonitor` app extension reliably tracks out-of-app distractions and clears shields even if the main app is killed.
- **Stats & Streaks:** Gamified retention system tracking focus minutes, individual daily streaks, and group streaks, culminating in a group leaderboard.
- **Sign in with Apple:** Secure authentication backed by Firebase Auth.

## Tech Stack

- **UI:** SwiftUI (iOS 16+)
- **Architecture:** MVVM, Swift Concurrency (`async/await`), `@MainActor`
- **Backend:** Firebase (Auth, Firestore, Cloud Messaging)
- **Apple Frameworks:** `FamilyControls`, `ManagedSettings`, `DeviceActivity`, `ManagedSettingsUI`

## Project Structure

The app relies on multi-target architecture to function:
1. **Screen time demo:** The main SwiftUI application.
2. **StudyHallMonitor:** A `DeviceActivityMonitor` extension that runs in the background to handle interval starts/ends and threshold events (distraction detection).
3. **StudyHallShield / StudyHallShieldUI:** Extensions conforming to `ShieldActionDelegate` and `ShieldConfigurationDataSource` to render and handle interactions with the restricted-app shield overlay.

State is shared between the main app and extensions using an App Group (`group.com.davechengapps.screentimedemo`) and `UserDefaults`.

## Setup & Building

*Note: This project uses Apple's Family Controls, which has specific development constraints.*

1. **Physical Device Required:** The Screen Time APIs (`FamilyControls`, `ManagedSettings`) **do not work in the iOS Simulator**. You must build and run on a physical iPhone or iPad.
2. **Apple Developer Account:** An active Apple Developer account is required to provision the `Family Controls (Development)` entitlement.
3. **Firebase Setup:** 
   - You must provide your own `GoogleService-Info.plist`.
   - Enable "Sign in with Apple" in Firebase Auth.
   - Deploy the required Firestore security rules (see `firestore.rules`).

## Known Apple API Constraints

- **App Tokens are Device-Local:** The opaque `ApplicationToken` identifiers generated by the `FamilyActivityPicker` cannot be shared across devices. Whitelists and blocklists are strictly configured per-device.
- **System Exemptions:** Apple does not allow third-party apps to shield core system communication apps (Phone, Messages, FaceTime, Find My) or competing Screen Time apps.
- **Distribution:** While the development Family Controls entitlement works immediately locally, submitting this app to TestFlight or the App Store requires [requesting special approval from Apple](https://developer.apple.com/contact/request/family-controls-distribution).
